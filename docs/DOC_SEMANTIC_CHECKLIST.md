# 文档语义一致性清单（机器判不了，靠人）

> 定位：`scripts/docs-audit.js` 只能验「能算出唯一真值」的项（行数/计数/版本/枚举/布尔/跨仓版本）。
> 本清单是人类必须核对的部分。**发布前、以及任何改动下列内容时，逐项过一遍。**

## 一、改动类型 → 必须人工核对的断言

| 改动类型 | 必须核对 | 典型翻车 |
|---|---|---|
| 设置项位置/入口变化（如搬页、改折叠卡） | 所有写「在哪儿点」的句子：FAQ、README、DOWNLOADS、DEV_CONVENTIONS | 文档还指旧路径，用户找不到入口 |
| 章节增删 | 文内 `## 一/二/三…` 编号是否连续、有没有「见第 X 节」指错 | 编号乱序（曾出现 十→十二→十三→十一） |
| 行为/默认值语义变化 | 描述「为什么/何时触发/默认是什么」的段落 | 默认值改了，解释段还按旧值写 |
| 删除/重命名文件 | 文档里的代码路径、文件名、「N 行」这类引用 | 引用指向不存在的文件 |
| 跨仓（音源 / track-player） | 另一仓对应章节：MUSIC_SOURCE_GUIDE、UPSTREAM_LIFECYCLE、MERGE_GUIDE | 版本号、commit 停在旧值（已加构建闸门兜底） |
| 新增/删除公开能力 | 能力清单（平台数、音质档、ABI、权限）是否漏项 | 「六大平台」实际 7 个这类自相矛盾 |

## 二、机器已覆盖的项（不必人肉重查）

见 `scripts/docs-audit.js` 18 条规则：TS 计数（全文档）、downloadManager 行数、ABI 清单、compileSdk/targetSdk/minSdk、音频卸载默认值、i18n 总键与 `dl_` 键、底座 bN、track-player commit、跨仓音源版本。

## 三、图文/表格类

- 截图、对比样张、表格里的数字与正文是否同源（图不会自动跟着改）。
- 表格列数/表头与新增字段是否匹配。

## 红绿自检（机制自身改动后必须跑，否则等于没装）

```bash
# 1. 红：把某文档里的一个数字改错 1 位
node scripts/docs-audit.js --dry-run    # 必须报出 🟡/🔴 且指对文件与旧值
# 2. 绿：自动修回真值
node scripts/docs-audit.js
# 3. 确认只改回该数字，没误伤别处
git diff
```

> 只用「跑完打印一堆绿字」当作机制生效，等于自欺——绿字可能是规则根本没命中。
